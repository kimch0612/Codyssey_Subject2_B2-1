# 나만의 용돈 기입장 프로그램 만들기

`Subject.txt`의 필수 요구사항을 기준으로, **작은 기능을 완성하면서 확장하는 순서**로 정리했어. 각 단계의 확인 항목이 통과하면 다음으로 넘어가면 돼. 보너스 과제는 제외했어.

### 1. 거래 데이터 모델 — `models.py`

- [ ] `Transaction`을 `dataclass`로 정의하기
- [ ] 필수 필드 정의하기: `id`, `type`, `date`, `amount`, `category`
- [ ] 선택 필드 정의하기: `memo`, `tags`
- [ ] 각 필드의 타입 힌트와 선택 필드의 기본값 정하기
- [ ] 금액은 CSV 스키마와 일치하도록 양수 정수로 다룰 준비하기

**확인:** 직접 거래 객체 하나를 만들고 각 필드 값을 확인할 수 있다.

### 2. 저장소 기본 기능 — `storage.py`

- [ ] `TransactionRepository` 등 저장소 클래스 정의하기
- [ ] 저장 폴더를 외부에서 전달받도록 만들기
- [ ] JSONL 형식으로 거래를 한 줄씩 읽는 제너레이터 구현하기
- [ ] 거래 한 건을 파일에 추가하는 기능 구현하기
- [ ] 카테고리와 예산의 읽기·쓰기 기능 구현하기
- [ ] 저장 폴더·파일이 없을 때 자동 생성하거나 초기화 안내하기
- [ ] **빈 카테고리 파일** 처리 정책 정하기: 기본값 생성 또는 등록 안내

**확인:** 거래를 저장한 뒤 프로그램을 다시 실행해도 읽을 수 있다. 현재 만들어둔 빈 파일도 정상 처리한다.

### 3. 실행과 CLI 뼈대 — `__main__.py`, `cli.py`

- [ ] `python -m budget_app`으로 실행되도록 연결하기
- [ ] `argparse`로 명령을 구분하기
- [ ] `category add/list/remove`, `budget set`의 중첩 명령 구성하기
- [ ] 저장 폴더 변경 옵션 연결하기
- [ ] 모든 명령에서 도움말을 출력하도록 만들기
- [ ] 원문의 `-` / `--` 충돌에 대한 처리 방침을 정하고 기록하기

**확인:** 도움말이 출력되고, 지정한 저장 폴더를 사용한다.

### 4. 카테고리 추가·조회 — `services.py`, `cli.py`

- [ ] 서비스 계층에서 카테고리 추가·조회 처리하기
- [ ] CLI에서 입력받아 서비스에 전달하기
- [ ] 결과를 CLI에서 출력하기
- [ ] 중복 카테고리 입력 시 동작 정하기

**확인:** 추가한 카테고리가 재실행 후에도 목록에 나타난다.

### 5. 거래 추가 — `add`

- [ ] 날짜·타입·카테고리·금액·메모·태그를 대화형으로 입력받기
- [ ] 날짜 형식과 실제 존재하는 날짜인지 검증하기
- [ ] 타입이 `income` 또는 `expense`인지 검증하기
- [ ] 금액이 양수 정수인지 검증하기
- [ ] 등록된 카테고리인지 검증하기
- [ ] 유일한 거래 ID 생성하기
- [ ] 검증에 성공한 거래를 저장하고 ID 출력하기
- [ ] 잘못된 입력은 재입력을 요구하거나 원인과 해결 힌트 출력하기

**확인:** 정상 거래는 저장되고, 잘못된 입력은 저장되지 않는다.

### 6. 거래 목록 — `list`

- [ ] 최신순으로 거래 출력하기
- [ ] `limit` 옵션과 **기본값** 제공하기
- [ ] 파일을 읽는 과정에서 제너레이터 사용하기
- [ ] 전체 거래를 리스트로 로드하지 않도록 구현하기
- [ ] 같은 날짜의 거래 간 정렬 기준 정하기

기존 노트의 `heapq.nlargest`를 활용할 수 있어.

**확인:** 날짜를 뒤섞어 입력해도 지정한 개수의 최신 거래가 나온다.

### 7. 거래 검색 — `search`

- [ ] 기간, 카테고리, 타입, 메모 키워드, 태그 검색 구현하기
- [ ] 여러 조건을 함께 적용할 수 있도록 만들기
- [ ] 검색 결과를 최신순으로 출력하기
- [ ] 제너레이터 기반 스트리밍 유지하기
- [ ] **결과 전체의 최신순 정렬과 메모리 사용을 함께 만족할 방법** 정하기

**확인:** 복합 조건에 맞는 거래만 나오며, 검색 결과를 모두 메모리에 쌓아 정렬하지 않는다.

### 8. 거래 수정·삭제 — `update`, `delete`

- [ ] `update` 입력 방식을 고정하기 — 기존 노트는 옵션 방식
- [ ] ID로 거래를 찾아 지정한 필드만 수정하기
- [ ] 수정값에도 거래 추가와 동일한 검증 적용하기
- [ ] 선택 필드의 “미지정”과 “내용 삭제” 구분하기
- [ ] ID로 거래 삭제하기
- [ ] 없는 ID는 안내 메시지와 오류 종료 코드로 처리하기
- [ ] 파일 재작성의 안정성 확보하기 — 임시 파일과 원자적 교체 권장

**확인:** 대상 거래만 바뀌고 다른 거래는 보존된다.

### 9. 카테고리 삭제 — `category remove`

- [ ] 해당 카테고리를 사용하는 거래가 있는지 검사하기
- [ ] 사용 중이면 삭제를 막거나 대체 카테고리를 요구하기
- [ ] 사용하지 않는 카테고리 삭제하기

**확인:** 거래가 존재하지 않는 카테고리를 참조하는 상태를 만들지 않는다.

### 10. 월 예산과 요약 — `budget set`, `summary`

- [ ] 월별 예산 저장하기
- [ ] 지정한 월의 총수입·총지출·잔액 계산하기
- [ ] 카테고리별 지출 합계 TOP N 출력하기
- [ ] `top` 옵션 지원하기
- [ ] 예산이 있으면 사용률과 초과 경고 출력하기
- [ ] 거래가 없는 달은 “데이터 없음” 출력하기

**확인:** 직접 계산한 값과 집계가 일치하고, 재실행 후에도 예산이 유지된다.

### 11. CSV 가져오기·내보내기 — `import`, `export`

- [ ] UTF-8, 헤더 포함 CSV 처리하기
- [ ] 스키마 고정하기: `date,type,category,amount,memo,tags`
- [ ] `tags`를 쉼표 구분 문자열로 변환하기
- [ ] 가져오는 거래에 기존 검증 로직 적용하기
- [ ] 처리 건수 출력하기
- [ ] 내보내기에 월 또는 시작일·종료일 조건을 필수로 받기
- [ ] 조건에 맞는 거래를 CSV로 저장하기

**확인:** 한글, 쉼표가 있는 메모, 여러 태그가 올바르게 읽히고 저장된다.

### 12. 공통 처리와 최종 점검

오류 처리는 앞 단계부터 구현하고, 이 단계에서 반복된 코드를 정리하면 돼.

- [ ] 공통 관심사 데코레이터를 직접 구현하고 실제 적용하기
- [ ] 오류 출력이 원인과 해결 힌트를 포함하도록 통일하기
- [ ] 사용자에게 스택트레이스가 노출되지 않도록 처리하기
- [ ] 정상 종료 `0`, 오류 종료는 `0`이 아닌지 확인하기
- [ ] 최소 3개 모듈, 2개 클래스, 3개 저장 파일 조건 확인하기
- [ ] 타입 힌트와 계층별 책임 점검하기
- [ ] Python 3.10 이상, 표준 라이브러리만 사용하는지 확인하기
